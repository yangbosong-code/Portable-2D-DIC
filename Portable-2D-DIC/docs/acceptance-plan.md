# 分阶段验收计划

## A. 软件回归（当前开发机，可自动完成）

| 项目 | 通过条件 |
|---|---|
| CPU/CUDA 准确性 | 合成整数及亚像素平移测试通过，无 NaN/越界/崩溃 |
| 应变 | 解析位移场的 `exx/eyy/exy` 在测试容差内 |
| 长度和 CRC | 损坏或截断的数据包必须拒绝 |
| Edge 状态 | START/STOP/RESET 非法顺序返回明确错误 |
| 断线 | Studio 退出不停止 Edge 会话，重连成功 |
| 保存 | manifest 与 `.p2dic` 可重新读取，CRC 正确，帧号和时间单调；离线 CSV 一致 |
| UI | 无显示器的 offscreen 测试能够渲染预览、云图和曲线 |

每次发布必须保存四套 CTest 结果：CPU/Qt、CUDA、GalaxySDK、GalaxySDK+CUDA。

## B. 相机验收（拿到 ME2P-1840-21U3M 后）

1. 核对序列号、固件、GalaxySDK 版本和 USB 拓扑；相机独占 USB3 控制器优先；
2. Mono8、4504×4096、自由采集，连续 30 分钟；
3. 目标不少于 10 fps，记录平均、P1、掉帧、超时和 USB 重连次数；
4. 分别测试 5/10/15/21.4 fps 请求值，找出稳定上限；
5. 曝光必须短于帧周期且图像不过曝，增益优先保持低值；
6. 测试软件触发和外部触发，核对时间戳与 GPIO；
7. 拔插、服务重启、相机占用、超时后均不得导致无提示崩溃。

建议门槛：连续 30 分钟零进程崩溃；目标档位有效帧率 ≥10 fps；帧号不连续必须被记录，
不能静默丢帧。21.4 fps 是相机标称满帧能力，不是本系统承诺值。

## C. Jetson 验收

1. 先确认大恒 ARM64 SDK 与目标 JetPack/Ubuntu 组合；
2. 安装后执行 `systemctl status p2dic-edge` 和 `dic_ctl PING`；
3. 记录 4504×4096 下采集、DIC、保存同时进行的 fps、P95/P99 延迟、CPU/GPU/内存/温度；
4. 测试 10 fps，再测试 15 fps；仅在二者稳定后尝试 21.4 fps；
5. 断开 Studio、断网、重启 Studio，Edge 必须继续会话；
6. 断电恢复、SSD 写满、相机断开和过热降频要有明确状态与可恢复行为；
7. 连续 8 小时压力测试，正式交付前再做 24 小时测试。

建议门槛：有效点计算吞吐持续 ≥10 fps；P95 端到端延迟先设为 ≤200 ms；零崩溃；
温度不触发持续降频；磁盘不足时停止新会话并保留已有数据。实测后再收紧指标。

## D. 测量学验收

| 实验 | 建议初始门槛 | 目的 |
|---|---:|---|
| 静止零载 5 分钟 | 位移标准差 ≤0.03 px | 噪声底 |
| 已知刚体平移 | 平均误差 ≤0.05 px | 位移准确性 |
| 往返位移 20 次 | 回程差 ≤0.05 px | 重复性 |
| 解析/标准应变 | 误差 ≤100 με 或相对误差 ≤5% 中较宽者 | 应变链路 |
| ROI 边缘与低纹理 | 必须失效标记，不得输出伪高质量值 | 安全性 |

这些是首轮工程门槛，不是计量认证。最终阈值必须由视场、镜头、散斑、材料和比赛/课题要求
共同确定，并记录像素到毫米的标定不确定度。

## E. 发布判定

只有 A–D 的证据都保存后，才能把版本标为“硬件验收完成”。当前没有相机和 Jetson，
因此只能完成 A 和部署包静态检查；B–D 必须保留为待办。
