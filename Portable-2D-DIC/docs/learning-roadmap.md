# 从零学习路线与三人分工

目标不是先学完所有知识再开工，而是用本工程逐级完成可验证的小闭环。建议每周 8–12 小时，
12–16 周走完无硬件开发阶段；拿到相机和计算盒后再安排 3–5 周联合验收。

## 共同基础（第 1–2 周）

三人都需要理解：单目 2D-DIC 测量的是与成像平面平行的位移；散斑、刚性、光照、曝光和
失焦会直接影响结果；模拟通过不代表真实测量通过。共同运行一次 CPU Edge、Studio 和自动测试，
能够解释参考帧、当前帧、subset、grid、ZNCC、亚像素、位移和应变的含义。

通过标准：能从 VS Code 构建 CPU 版本，启动 Edge/Studio，并完成一次模拟 START/STOP 会话。

## 计算机开发人员

### 第 1 阶段：C++ 与工程基础（第 1–3 周）

- C++：RAII、`std::vector`、智能指针、线程、互斥量、条件变量、异常；
- CMake/CTest：target、链接库、preset、自动测试；
- 阅读顺序：`ICamera` → 合成相机 → DIC 接口 → CPU ZNCC → runtime pipeline。

练习：修改合成相机位移速度，让测试仍通过；新增一个不会破坏协议的状态字段。

### 第 2 阶段：DIC 算法（第 4–6 周）

- 整数 ZNCC 搜索、纹理质量、边界检查；
- Gauss–Newton 亚像素迭代、双线性插值、收敛与失效条件；
- 位移梯度、局部最小二乘和小应变；
- 用 CPU 教学实现作为真值参考，不从 CUDA 内核开始学算法。

通过标准：能够说明一个点失效的原因，并用合成平移/解析应变测试定位误差。

### 第 3 阶段：CUDA 与实时系统（第 7–10 周）

- CUDA 的 grid/block/thread、显存、共享内存、同步、错误检查；
- 固定内存、异步流水、最新帧优先和背压；
- 用 Nsight Systems/Compute 查瓶颈，禁止只看 CUDA kernel fps；
- 理解控制、结果、预览三条 TCP 通道及 CRC。

通过标准：CUDA 准确性测试通过；能区分采集 fps、计算 fps、显示 fps 和端到端延迟。

### 第 4 阶段：Qt 与部署（第 11–16 周）

- Qt signal/slot、网络、线程边界、绘图控件；
- systemd、日志、健康检查、断网/重启恢复；
- 修改中文界面时保留英文参数名和英文日志关键字。

通过标准：Studio 断开不影响 Edge 会话；重新连接后可恢复状态和实时显示。

## 实验人员

- 第 1–2 周：理解参考图像、ROI、subset/grid 与质量阈值；
- 第 3–4 周：学习曝光/增益/直方图、散斑尺寸和离焦判断；
- 第 5–6 周：建立零载、刚体平移、已知位移和重复性实验；
- 硬件阶段：每次实验记录镜头、工作距离、视场、曝光、增益、温度、帧率和掉帧。

通过标准：不改代码也能按照验收表复现实验，并能判断低质量点来自图像还是算法参数。

## 物理/机械人员

- 设计相机、镜头、光源和试件的刚性安装；
- 根据 1 英寸靶面和目标视场选镜头，检查 C/CS 接口、后焦距、畸变和景深；
- 设计散热、线缆应力释放、防触碰结构和可重复装配基准；
- 提供标尺/位移台/应变标准件，定义允许误差，而不是只观察云图“是否好看”。

通过标准：空载静止和已知刚体位移满足验收阈值，重复拆装后标定漂移有记录。

## 推荐阅读代码顺序

1. `include/p2dic/types.hpp` 与 `camera.hpp`；
2. `src/synthetic_camera.cpp`、`src/pgm_camera.cpp`；
3. CPU ZNCC 与亚像素实现；
4. `src/runtime.cpp` 和 Edge 状态机；
5. 结果/预览数据包与 TCP 服务；
6. `src/cuda_grid_engine.cu`；
7. `studio/`；
8. `deploy/jetson/`。
